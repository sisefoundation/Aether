# AETHER conform engine specification

Status: proposal for review. Specification only. The engine was not implemented and no sequence was conformed. Illustrative identifiers are not run output.

## Verified facts

- Conform is specified as a separate architecture in `ONLINE_CONFORM_ARCHITECTURE.md`: editorial records in, report out, export and relink are not verdicts.
- Time and speed maps are specified in `SOURCE_TIMECODE_AND_FRAME_ACCURACY.md` and `SEQUENCE_SOURCE_MAPPING.md`.
- The registry can return an asset while every file is offline (`MEDIA_REGISTRY_SCHEMA.md`).
- No conform report was generated by a program for this document.

## Engineering recommendations

- Implement the engine as a pure pass over a pinned revision plus registry reads, then a single report write.
- Keep effect evaluation symbolic: compare the stored effect definition with a capability table. Do not rasterise an effect to decide that it “looks right”.
- Fail closed. Missing data is `incomplete` or `manual_review_required`, and a contradiction is `failed`.

## Proposed behaviour

### Scope

The conform engine is the component that performs the steps and comparisons in the online architecture. This document specifies inputs, the per-instance record it builds, ordering, and how it treats gaps, overlaps, sync, and effects. The report file format is `CONFORM_VALIDATION_AND_REPORTING.md`.

### Requirements

Inputs the engine reads for each instance, from the editorial model and the registry, not from a preview file:

| Input | Record |
| --- | --- |
| Sequence id | Sequence revision pinned at start |
| Instance id | Timeline instance |
| Media id | Original Media ID |
| Timecode | Source start and the instance’s source in and out as timecode labels when start availability is `present` |
| In and out | Stored half-open source range and record range |
| Duration | Record duration and source duration implied by the map |
| Speed | The speed map |
| Track | Track id, kind, and order |
| Audio | Channel map and sample-rate relationship |
| Timebase | Sequence rate and source rate |
| Effects | Effect and transition definitions on the instance |

Steps, normative order:

1. Identify the sequence and pin the revision.
2. Read tracks, instances, transitions, and gaps as structure.
3. Resolve each instance to a master clip or subclip.
4. Resolve each editorial object to a Media ID.
5. Locate the original representation through the registry. Relink may be invoked to refresh locations. Its success is logged and is not the conform state.
6. Verify identity with the match rules. Critical auto-accept is `exact` or an explicitly validated decision.
7. Verify timecode and source range against the original’s frame count and start timecode.
8. Reconstruct timing and tracks from stored integers and compare them with the structure read in step 2.
9. Evaluate effects and transitions against the support table.
10. Check sync between picture instances and their linked audio instances.
11. Write the report.
12. Attach the discrepancy list.
13. Set the state. `verified` and `verified_with_warnings` are allowed only when every critical check passed.

Comparisons, each producing a discrepancy or a pass:

- Sequence duration and sequence rate.
- Track count and track order.
- Clip count and instance identity.
- Media ID.
- Source in and source out.
- Record positions.
- Instance durations.
- Speed maps.
- Transitions.
- Sync.
- Source mapping.
- Missing media and missing effects.
- Unsupported effects.
- Unintended gaps and unintended overlaps.

An intended gap is the absence of an instance where the editorial model has no clip and no “gap was accidental” flag. The engine does not invent intention. A gap is unintended when a transition or an abutting pair of instances leaves a hole that the stored record ranges did not declare, or when a receiver reconstruction (during an exchange conform) inserts one. Inside AETHER, reconstruction must equal the stored model. Any inequality is a failure of the engine or of the data, and the state is `failed`.

### Data model

Per-instance working record (not a second editorial store):

```text
conform_item
  instance_id
  media_id
  identity_class
  identity_decision_id
  range_ok
  timing_ok
  speed_ok
  sync_ok
  effects           list of {effect_id, support}
  discrepancies     list
```

`support` uses the AVX preservation vocabulary: `native`, `mapped`, `metadata_only`, `rendered_fallback_retained`, `unsupported`.

Critical flags, failure of any one blocks `verified`:

- identity not `exact` and not explicitly validated;
- original representation missing or validation not `passed` when the target role is original;
- source range outside the original;
- record position or duration disagreement;
- speed map disagreement;
- linked audio that the frame-only model cannot represent (ADR-002). A fractional-sample mapping is not this failure;
- effect or transition `unsupported` (blocks `verified`; may be `verified_with_warnings` only if the policy allow-list names that effect type — default allow-list is empty).

### APIs

The operations are `Conform.inspect`, `Conform.run`, and `Conform.read` in `ONLINE_CONFORM_ARCHITECTURE.md`.

Internal steps are functions of plain data:

| Step function | Reads | Writes |
| --- | --- | --- |
| `pin` | Sequence | Run header |
| `resolve` | Editorial objects, registry | `conform_item` list |
| `compare` | Items, maps, effects | Discrepancies |
| `judge` | Discrepancies, policy | State |
| `publish` | State and items | Report document |

`publish` is the only step that writes a durable conform artifact. None of the steps write instance source ranges.

### Workflow

The application pins a revision, calls `Conform.run`, and stores the run id on the sequence as “latest run for this revision”. A newer revision does not delete the old run. The user opens the HTML report. If the state is `manual_review_required`, the user either validates matches in the relink sense or changes the cut with editorial commands, then runs conform again on the new revision.

Exchange conform, when a package comes back, is a second mode: `Conform.runAgainstDocument(sequence_id, document)`. It compares the native revision to the document’s reconstructed structure. The native project remains the authority. The document does not overwrite it. Disagreements are discrepancies.

### Validation

The engine’s own output is validated before it is shown:

- every instance in the revision appears exactly once in the report;
- every discrepancy names an instance id or a sequence-level code;
- the state agrees with the critical flags;
- `verified` has an empty critical list;
- the report hash in the run header matches the body.

A self-check failure publishes `failed` with reason `engine_inconsistent` and no approval.

### Errors

| Error | State |
| --- | --- |
| Revision disappeared | `failed` |
| Registry unavailable | `failed`. Instances are not marked missing media merely because the database did not open. |
| Original offline | `incomplete` |
| Ambiguous identity | `manual_review_required` |
| Range mismatch | `failed` |
| Unsupported effect, default policy | `manual_review_required` if identity otherwise passed, else the worse state |
| Preview path supplied as an original | Ignored as an input. If the caller has no registry id, `failed` with `proxy_not_original`. |

### Recovery

The run is immutable after publish. A bad run is superseded by a new run. Recovery of the project never needs the conform report in order to open the cut. Losing the report loses the verdict, not the sequence. The UI then shows “no conform for this revision”.

### Performance

The pass is linear in the number of instances, transitions, and effects, with indexed registry lookups. It does not decode essence. If checksums required for `exact` are pending, the state is `incomplete` with reason `checksum_pending`, and a background job may be requested. The engine does not block on the hash inside `judge`. No duration was measured.

### Tests

Test G, specified and not executed. The fixture set must cover each comparison row, including an unintended overlap, a missing original, an ambiguous match, a ramp checked by its segment list, a successful export event that does not change the state, and a successful relink that does not change the state.

### Acceptance

- Inputs and the thirteen steps match the brief.
- The comparison list is complete.
- Preview files and proxy paths are specified as non-sources.
- The engine writes a report and does not write the cut.

## Unresolved questions

- Nested sequences. Recommendation in the online architecture: child runs. Confirm before phase 6.
- How large a discrepancy list is embedded versus referenced. Recommendation: embed all of them. Feature sequences are thousands of rows, which a JSON file can hold. Streaming the HTML is a presentation concern.
- Whether a warning allow-list is a project setting. Recommendation: yes, default empty, and the report prints the allow-list so a `verified_with_warnings` result is explainable.
