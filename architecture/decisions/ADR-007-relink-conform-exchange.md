# ADR-007 — Relink, conform, and exchange are different results

- Status: **PROPOSED**
- Date: 2026-11-20
- Deciders: not decided. The conform and relink specifications already separate them.
- Related: `docs/MEDIA_RELINK_ENGINE.md`, `docs/CONFORM_ENGINE_SPECIFICATION.md`, `docs/CONFORM_VALIDATION_AND_REPORTING.md`, `docs/EXCHANGE_COMPATIBILITY_MATRIX.md`, `docs/INTERCHANGE_ADAPTER_ARCHITECTURE.md`

## Context

A cutting room uses the words relink, online, conform, and export for different events. Collapsing them makes a path update look like a verified picture match, and makes a rendered file look like a database.

## Decision

**PROPOSED.**

- Relink may change location rows for a known Media ID after classification and validation. It does not change instance ids, record ranges, or Media IDs. Its result is not a conform state.
- Conform reads a pinned sequence revision and the registry, compares structure, identity, time, and effects, and writes a report. `verified` is allowed only when the critical checks passed. Export does not set that state.
- Exchange writes a translation (AVX, AAF profile, OTIO, FCP XML, FCPXML, or CMX 3600 EDL) plus a loss report. The native project remains the source of truth. No adapter is a verified interchange with another vendor until a test against that application is recorded. None is recorded.

## Consequences

- UI copy can say “relinked”, “export finished”, or “conform verified” only for the operation that actually ran.
- An EDL is a reduced list. It is never the only save of the cut.
- A prior FFmpeg mux is not a conform and is not a vendor test.

## Alternatives

- Treat a successful export preset as conform. Not proposed.
- Treat filename match as relink. Not proposed. Filename-only match is insufficient (`docs/MEDIA_STORAGE_AND_RELINKING.md`).

## Confirmation

None. No conform report has been generated by a program in this repository.
